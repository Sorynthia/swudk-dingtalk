# 服务开关与星轨风格改造设计

## 目标

为西大寝签增加默认关闭的服务级环境变量开关，并将现有页面统一改造成参考 `C:\Users\Admin\Documents\Repositories\portfolio` 的暖色星轨风格。

完成后应满足：

- 只有 `SERVICE_ENABLED=true` 时业务功能可用。
- 环境变量缺失、为空、为 `false` 或为其他非法值时，服务保持关闭。
- 服务关闭时不生成或轮询二维码，不读取学生资料，不查询或提交签到，也不调用钉钉及校内上游服务。
- 服务关闭时首页只展示维护状态，不呈现任何业务操作控件。
- 关闭状态下仍允许退出登录，以便清理旧会话和 Cookie。
- 服务开启时保留现有登录、住宿查询、签到和会话行为。

## 服务开关架构

新增独立服务状态模块，负责读取和解析 `SERVICE_ENABLED`。解析规则为先去除首尾空格、再忽略大小写比较；只有结果严格等于 `true` 时返回开启，其他情况全部返回关闭。

所有入口均使用同一状态模块：

- `src/app/page.tsx` 在读取 Cookie 或查询签到状态前检查开关。关闭时直接渲染维护状态。
- `src/app/api/auth/qr/route.ts` 的 `POST` 在来源校验和业务处理前拒绝请求。
- `src/app/api/auth/status/route.ts` 的 `GET` 在读取会话和轮询前拒绝请求。
- `src/app/api/auth/session/route.ts` 的 `GET` 在读取会话前拒绝请求。
- `src/app/api/profile/route.ts` 的 `POST` 在来源校验和资料刷新前拒绝请求。
- `src/app/api/check-in/route.ts` 的 `GET`、`POST` 在读取会话或访问校内服务前拒绝请求。
- `src/app/api/auth/session/route.ts` 的 `DELETE` 不受开关限制，继续校验来源并清除服务端会话及 Cookie。

关闭时业务 API 统一返回 HTTP `503` 和中文 JSON 消息，明确说明服务暂未开放。该响应不包含内部配置值或部署细节。

## 页面与组件

`AppShell` 增加明确的服务可用状态输入。关闭时只渲染独立维护界面；开启时继续根据会话状态渲染登录页或信息页。服务可用状态由服务端页面确定，不从浏览器环境变量推断。

维护界面包含：

- “西大寝签”品牌标识；
- 星轨主题视觉标识；
- “服务暂未开放”标题；
- 简短的状态说明；
- 不包含二维码、刷新、签到、重试或其他业务按钮。

登录页继续支持空闲、生成中、等待扫码、已扫码、二维码过期、失败和会话认证完成状态。二维码区域使用稳定尺寸，状态切换不得造成布局跳动。

信息页继续展示学号、住宿地址、签到半径、更新时间和签到状态，并保留资料刷新、临时签到及退出登录操作。信息展示采用清晰分组，不使用卡片嵌套。

## 视觉规范

视觉依据为本地 `portfolio` 项目的暖色星轨设计，不直接依赖或运行该项目代码。

- 背景使用暖白色与克制的径向光晕。
- 主色使用棕金色，正文使用暖深棕，状态色保留明确的成功、警告和错误语义。
- 顶栏为轻量悬浮胶囊形态，使用半透明背景、低对比边框和柔和模糊。
- 二维码或维护标识外围使用倾斜的椭圆轨道，并在轨道附近放置四角星芒。
- 主要按钮使用新拟态阴影：默认柔和凸起、悬停轻微上移、按下呈内凹反馈。
- 内容容器最大宽度受控，桌面与移动端均保留足够留白。
- 控件、二维码和状态区使用稳定尺寸，动态内容不能引发布局抖动。
- 不引入网络字体，沿用可靠的中文系统字体栈。
- 入场和状态动效保持克制，并在 `prefers-reduced-motion: reduce` 下禁用非必要动画与位移。
- 所有可交互元素保留键盘焦点样式、语义标签和足够的颜色对比度。

## 数据流与错误处理

开启状态的数据流保持现状：用户主动生成二维码，客户端轮询登录状态，认证完成后由服务端读取并返回脱敏资料，用户主动执行临时签到。

关闭状态的数据流在应用边界停止：

1. 页面请求在服务端开关检查处直接进入维护界面。
2. 业务 API 在任何 Cookie、会话或上游调用前返回 `503`。
3. 客户端不会渲染或触发业务操作。
4. 退出请求仍可在同源校验后清理旧会话。

服务关闭不是认证失败，因此使用 `503`，不返回 `401` 或 `403`。现有上游失败、会话过期和来源校验错误继续使用原有状态码及处理逻辑。

## 配置与文档

`.env.example` 增加：

```env
# 只有 true 时开放二维码登录、资料查询和临时签到。
SERVICE_ENABLED=false
```

README 说明默认关闭行为、允许值和部署时的开启方式。真实 `.env` 不写入设计或测试中的敏感配置，也不提交仓库。

## 测试策略

按测试驱动方式实施：先编写失败测试，确认失败原因是功能尚未实现，再完成最小实现并保持全量测试通过。

测试覆盖：

- 服务状态解析：`true`、混合大小写、首尾空格、缺失、空值、`false` 和非法值。
- 页面关闭状态：不读取会话、不查询签到，只渲染维护状态。
- 二维码、登录轮询、会话读取、资料刷新、签到查询和签到提交：关闭时返回 `503`，且相关业务函数不被调用。
- 退出登录：关闭时仍能删除会话并清空 Cookie。
- 原有二维码复用、会话切换、签到并发保护和认证失效测试继续通过。
- 桌面与移动端视觉检查：维护页、登录页、二维码等待状态和已登录信息页。
- 无障碍检查：键盘焦点、语义文本、移动端换行和减弱动画。

最终执行：

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

构建成功后启动本地服务，通过浏览器分别检查关闭和开启状态；视觉对比以本地 `portfolio` 页面及其源码为依据。

## 范围边界

本次不修改钉钉或西南大学上游协议，不迁移会话存储，不增加管理后台，不支持运行时无重启切换，也不修改参考 `portfolio` 仓库。环境变量变化在应用进程重启后生效。
